Frozen `PreviewAssetReading` says the result carries the actual coordinated location. Lane 06's coordinated `read` returns the caller's `IOSFileLocation` and keeps `payload.data` only. `IOSWorkspaceAccessService+Preview` then copies `coordinated.location.fileURL`. The file port stores the proved URL on `IOSWorkspaceFilePayload.coordinatedURL`, and the service does not publish it. The lane 06 receipt says a location built from the proved path is `.outsideGrant` under `authorize`, and symlink files throw `.outsideGrant` before bytes are returned.

That split stays. Publishing the proved URL would fight `authorize` and lane 07's root containment. Changing it requires a contract revision from lane 13, not a silent patch in the preview adapter.
