# Wire the isolated IOSAcceptance UI-testing target and bind validation required-name manifests to source provenance

Adds the iOS 26 UI-testing target `IOSAcceptanceUITests` hosted by `PlainsongIOS` under a dedicated `IOSAcceptance` scheme so an empty or skipped acceptance action cannot inherit the module suite's result, plus `make ios-acceptance` and `make ios-acceptance-components` outside `make test` and `make ios-test`. Updates `EditorReplaceLayeringTests.testNoProjectOrPackageDependencyChange` to include `IOSAcceptanceUITests` in the approved project target set while keeping package, dependency, and macOS layering assertions unchanged. Simulator test admission requires a single matching `.xctestrun`, an enabled plan, and a built Mach-O `.xctest` image (ignoring `.a`/`.swiftmodule` products) before execution, alongside non-empty resource preflight and preview bundle byte parity. `ios-provenance.py` includes `docs/ios/evidence/validation/required-hosted-smoke.txt` and `docs/ios/evidence/validation/required-component-tests.txt` in `INPUT_FILES`, and the runners capture read-only run-local copies for result verification so editing either required-name manifest during a run invalidates source verification and cannot weaken the named-case gate. `AcceptanceDebugSeam` remains disabled and production composition stays the unavailable C0 scaffold. Alternatives rejected: adding `IOSAcceptanceUITests` to the `PlainsongIOS` scheme, relaxing or skipping `EditorReplaceLayeringTests`, counting library products as compiled tests, or consuming mutable uncaptured required-name manifests after test execution.

references above describe the original decision date; current evidence is tracked in
