# Release 1.0 scope: V3, WYSIWYG leaves Experimental for 1.0

Date: 2026-11-11. Owner decision on `docs/release-1.0-scope.md` §1, V3.

## Decision

- **V3.** WYSIWYG is promoted for macOS 1.0. It leaves Experimental as draft #213
  describes: on by default and a stop in the layout cycle and the toolbar picker, not the
  first-launch layout, with the Settings switch kept as the kill switch.
- This sets the target. It does not close the gate: #213 merges only after
  `docs/wysiwyg-release-checklist.md` §D.4, which needs the owner's dogfood and actual-IME
  sign-off and #213's own Decision Log entry.

## Why

- The owner chose promotion when asked on 2026-11-11, knowing it costs the dogfood pass.
  The other option was the draft default: ship it Experimental and off by default, with
  no owner work.
- The dogfood stays a condition because the last real Zhuyin and Pinyin runs (2026-07-06
  and 2026-07-12) predate STTextView 2.4.1 (R9), and agent.md §13 makes IME correctness
  non-negotiable.

## Alternatives considered

- Ships Experimental, off by default: the draft default, not chosen.
- Promoting without the dogfood: not offered. §D.4 and agent.md §13 require it.

## Consequences

- macOS 1.0 now waits on the §D.4 gate. `docs/release-1.0-scope.md` §2 lists the
  promotion under Must, and §5 has its exit box.
- WYSIWYG's raw constructs (tables, fences, Mermaid/math, reference links, autolinks,
  SVG/remote/single-file images) stay deferred; promotion does not change them.
- If the dogfood finds a blocker, it is fixed before 1.0 or the owner revisits V3. This
  entry does not decide which.
- The README drops the Experimental label when #213 merges, not before.
