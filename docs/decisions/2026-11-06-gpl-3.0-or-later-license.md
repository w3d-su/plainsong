# License Plainsong under GPL-3.0-or-later, because the macOS editor links STTextView under GPLv3

The macOS editor links STTextView 2.4.1 (`Packages/EditorKit/Package.swift`, revision
`bbdcfd9d413ad3055dafd23a223be9bd39742f89`). Its license, copied to
`docs/third-party/STTextView-2.4.1-LICENSE.md`, lets an open-source application use it
under the GPLv3 when the application's own license is compatible with the GPLv3, and
requires a paid commercial license otherwise. Plainsong was MIT, and every alpha DMG
through `v0.1.0-alpha.5` combined that code with STTextView without the GPL text and
without saying that the shipped program is covered by the GPL. The owner chose to
relicense instead of buying the commercial license or replacing the editor component.

- `LICENSE` is the verbatim GNU GPL v3 text from https://www.gnu.org/licenses/gpl-3.0.txt
  (SHA-256 `3972dc9744f6499f0f9b2dbf76696f2ae7ad8af9b23dde66d6af86c9dfb36986`), matching
  the copy inside STTextView's license. The "or any later version" grant is in the README
  notice, so the file itself stays the unmodified license text.
- The macOS app copies `LICENSE` to `Contents/Resources/LICENSE`, so the license travels
  with every DMG. `NSHumanReadableCopyright` puts the copyright, the license, the absence
  of warranty and the source location in the standard About panel.
- A published release points to its corresponding source: the release tag in this
  repository, whose source archives GitHub lists next to the DMG. The release notes must
  say so (`docs/release-engineering-plan.md`, P0). The SwiftPM and npm dependencies come
  from public upstream repositories; if one of them disappears, the source for a release
  that shipped it has to be provided another way.
- A new dependency's license must be compatible with GPL-3.0-or-later (agent.md §2).

Code published before this change, including the sources of `v0.1.0-alpha.1` through
`alpha.5`, stays available under MIT to anyone who received it. Bundled third-party
components keep their own licenses (Sparkle, KaTeX, Mermaid, highlight.js, the unified
packages, morphdom, Yams, SwiftTreeSitter and the tree-sitter grammars). A consolidated
third-party notice inside the app bundle is a separate follow-up.

The iOS app does not link STTextView, but it is part of this repository and is now
GPL-3.0-or-later as well. The commit history has no outside human authors, so the owner
can still license their own code differently, for example for a store build that contains
no third-party GPL code. Outside contributions accepted under the GPL would need their
authors' permission for that, so a CLA or DCO policy should be settled before the first
one is merged.

Alternatives:
- Buy the STTextView commercial license and stay MIT: not chosen now. Because the owner
  holds the copyright, it remains the way back to a permissive license or a closed build.
- Keep the source MIT and declare only the shipped macOS binary GPL-covered (MIT is
  compatible with the GPLv3): a smaller change, but one program would carry two licenses,
  and code that only works under the GPL could enter the repository unnoticed. Rejected in
  favor of one license that matches what ships.
- Replace STTextView with `NSTextView` and TextKit 2 (the fallback named in the 2026-06-12
  STTextView decision): months of editor work and new IME risk.
- GPL-3.0-only: equally compatible with STTextView. "Or later" is the notice the FSF
  recommends; switching to "only" changes the README notices, `NSHumanReadableCopyright`
  and this record, not `LICENSE`.
